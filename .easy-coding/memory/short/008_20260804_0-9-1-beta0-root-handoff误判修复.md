## 技术记忆候选

- 架构 / 接口决策：`task.json.last_agent` 使用平台 Agent 身份；Codex 内部协作路径 `/root`、`/root/...` 在状态 API 边界规范化为 `codex`。
- 工程规则 / 工作流：Agent 身份必须在写入和比较两侧同时规范化；只修状态行展示会留下任务列表、claim 和后续写入的不一致。
- 实现模式 / 复用写法：使用 `normalize_agent_identity` 与 `agents_equivalent` 收口身份规则；存量读取兼容与新写入规范化并行，避免运行时数据迁移。
- 易错点 / 修复策略：状态 API 原先虽计算了规范化 session agent，却继续把原始 `args.agent` 传给业务命令；修复时必须统一命令分发，同时保留自定义 Agent ID 的原始大小写与真实跨平台差异。
- 验证经验：共享 hook 身份修复需覆盖状态行、machine breadcrumb、list-tasks、claim、真实跨平台 takeover，并执行全量 hook/平台安装测试与 npm 包验证。
