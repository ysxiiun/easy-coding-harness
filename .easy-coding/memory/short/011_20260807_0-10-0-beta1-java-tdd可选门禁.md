# 0.10.0-beta.1 Java 可选 TDD 门禁

## 任务摘要

- 目标：为 Java 项目增加默认关闭、可按项目或会话开启的严格 TDD 模式，并把修改代码单测覆盖率作为可配置验收门禁。
- 范围：配置 schema 与 CLI、独立 `ec-config` skill、任务快照与状态栏、ANALYSIS/IMPLEMENT/REVIEW/VERIFICATION 工作流、JaCoCo 修改行覆盖率工具、升级兼容、文档与自动化测试。
- 结果：已完成；TDD 默认关闭，仅 Java 代码任务可生效，开启后状态栏展示 `TDD`，覆盖率设计努力接近 100%，默认验收阈值为 90% 且支持配置；项目级配置和会话级 override 均由 `ec-config` 管理。
- 关键约束：TDD 关闭时不增加额外测试/覆盖率门禁成本；任务创建时冻结 TDD 开关、阈值与配置 SHA；非 Java 或无代码变更任务强制关闭；本轮记忆生成时尚未提交、推送或发布 npm。

## 技术记忆候选

- 架构 / 接口决策：TDD 是独立可选模式，不复用 `ec-task-management` 承载配置；`ec-config` 统一管理项目级 CLI 配置与当前会话 override，任务快照冻结 effective TDD、覆盖率阈值和配置 SHA，避免执行中配置漂移改变验收合同。
- 工程规则 / 工作流：项目默认 `tdd.enabled=false`、`coverage_threshold=90`；只有 Java 代码任务开启严格 TDD，ANALYSIS 需要先设计测试，IMPLEMENT 遵循 red-green-refactor，VERIFICATION 必须验证本地与 CI 覆盖证据达到冻结阈值。
- 实现模式 / 复用写法：状态栏仅在 effective TDD 开启时插入 `TDD`；覆盖率工具基于 Git diff 的 Java 修改行与 JaCoCo XML 计算 changed-line coverage，支持未跟踪文件、传统/自定义源码布局、Maven module/aggregate 报告和同名源文件消歧。
- 易错点 / 修复策略：旧 schema 中即使出现自定义 TDD 字段也必须按关闭迁移；非 Java、无代码任务和 TDD 关闭态不得触发覆盖率脚本或额外证据检查；报告过期、源码映射歧义、目标源文件缺失均必须失败而非静默放行。
- 验证经验：除配置/状态机测试外，必须用真实临时 Git 仓与 JaCoCo fixture 覆盖 tracked、untracked、多模块、aggregate、legacy layout、ambiguous source、stale report 和 threshold pass/fail；发布包需确认同时包含 `ec-config` 与 Java 覆盖率工具。
