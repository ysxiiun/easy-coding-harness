# 0.10.0-beta.9 结构化 handoff 根治

## 任务摘要

- 目标：根治 Codex/Qoder 共用约束、展示署名和 owner 混用导致的虚假 handoff，避免继续依赖字符串差异推测交接。
- 范围：工作流状态脚本、平台模板上下文、任务/session 类型与升级迁移、三平台主约束、文档和回归测试。
- 结果：已完成。handoff 改为显式 `handoff`/`claim` 协调事件驱动，安装后的状态脚本固化宿主身份，状态写入执行三方一致性校验。
- 关键约束：可变状态只写 `claude-code` / `codex` / `qoder`；作者和 Canonical 展示归属仍可使用 `Codex with Easy Coding`，历史 `execution.jsonl` 不重写。

## 技术记忆候选

- 架构 / 接口决策：平台 owner、展示归属和交接状态是三个独立概念；安装产物内嵌平台身份，`--agent` 与 session 命名空间必须同时匹配。
- 工程规则 / 工作流：`last_agent` 只表达当前 owner；handoff 是否待消费以 `execution.jsonl` 中最新的 `handoff`/`claim` 协调事件为准。
- 实现模式 / 复用写法：`claim-task` 追加 immutable `claim` 记录作为消费 handoff 的提交事实；Codex/Qoder 共用的 `AGENTS.md` 必须与安装顺序无关并同时描述两平台路径。
- 易错点 / 修复策略：升级只规范化 task/session 等可变 owner 字段，保留历史执行归属；首次 SessionStart 的旧 `state.json` 迁移和已是当前版本的幂等升级也必须能自愈展示名污染。
- 验证经验：根治身份串用需要同时覆盖安装脚本固化身份、脚本/参数/session 三方错配、无 handoff 事件不展示、handoff 后展示、claim 后关闭、beta.8 整链升级与历史执行日志不变。
