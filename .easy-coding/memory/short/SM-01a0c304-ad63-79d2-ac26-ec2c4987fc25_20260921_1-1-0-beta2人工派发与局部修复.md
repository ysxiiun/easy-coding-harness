## 技术记忆候选

- cooperate_mode 为 default 或 dispatch，默认 default。default 保持阶段节点交接；dispatch 支持用户手动派发实施和 QUALITY 内的普通修复，不绑定平台，不自动调度其他 Agent。用户可以选择主 Agent 直接修改。
- 派发前一次确认范围与执行人，合并所需审批；Guard、Confirm、Auto 仍保留人工选择，接手方不再次审批已接受的工作。handoff 携带 next_action、原 Unit ID、证据索引和 stop_after，执行方完成后交回验证。
- 普通代码和测试修复留在 QUALITY，Review/Verification 本身保持只读。只有需求、契约、范围或主要实施方案变化才退回 ANALYSIS/IMPLEMENT；严重程度和行数不单独决定回退。begin-correction 登记范围，start-quality-repair 接受执行授权，complete-quality-repair 完成回交。
- approval_mode、cooperate_mode、unit_test_mode、ut_coverage_threshold 按字段使用会话 > 本地 ~/.easy-coding/config.yaml > 项目 > 默认值。读取、初始化和升级不创建本地文件，首次明确保存才创建，reset 删除所选覆盖项。本地 UT/TDD 偏好可以在项目外保存，任务实际启用时检查 readiness；冻结单测契约和已授权接力不被默认配置修改覆盖。
- 本机默认派发命令为 easy-coding config --scope local --cooperate-mode dispatch；项目使用 --scope project，会话通过 ec-config 设置。
- claim 对同一活动会话幂等；spec_contexts 按 session 保留消费凭据，原会话接回未变设计时直接复用，丢失上下文或设计变化时才显式 resume-spec-context。
- 指纹格式与旧证据保留，升级不全量重算。输入绑定检查以真实命令、Unit、来源和维度识别，展示名称及普通 argv 等价格式不触发重复运行；shell 展开、参数、输入和配置变化仍使相关证据失效。历史无 inputs 的手写记录保留既有覆盖语义。
- 一次状态 API 操作共享输入、日志和计划快照；prepare-check/record-check 支持批量处理。修复后只补增量审查和受影响验证，引用未变输入的旧成功结果。
