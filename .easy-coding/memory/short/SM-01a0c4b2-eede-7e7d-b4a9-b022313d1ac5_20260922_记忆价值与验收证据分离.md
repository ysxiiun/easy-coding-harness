# 开发记忆与验收证据的职责边界

## 知识摘要

维护 MEMORY 时，优先判断一条事实能否指导后续理解、修改或排障。短期记忆必须直接可用；
验收依据保存在任务记录中，通过来源引用追溯。把验收字段设为记忆正文的必填项，会诱导
Agent 复制报告，并让真正的知识退居次要位置。

## 可复用知识

- 记忆合同需要同时协调 ec-memory、短期模板、平台主约束和 ec-analysis 的读取规则。
  标题与摘要描述知识主题，正文保留适用场景、有效结论、必要原因、代码入口和边界；不把
  单次任务的范围限制升级成全项目规则，也不为每条事实机械填满栏目。
- QUALITY→MEMORY 的验收记录和 Canonical 写回负责授权与质量追溯。memory-short-complete
  保留 schema、任务归属、UUID、路径和内容完整性校验；不要求再次把审批、差异指纹和验证
  策略复制到记忆。这两个职责必须分开，不能为了精简记忆而削弱实际验收。
- writeMemoryScaffold 只在缺失时创建 SHORT_MEMORY_TEMPLATE.md，升级会保留用户模板。
  所以新 ec-memory 指令必须明确优先于旧模板的过程栏目；只改出厂模板不能修复已安装项目。
  历史记忆保持原样，正常蒸馏时从候选提取有效知识，不进行全库改写。
- default 与 dispatch 使用相同的知识标准。协调者直接复用已有 Spec、实施结果和 Review
  发现，不再索要一份记忆报告。没有新增知识时使用 memory_value: none / target_long: NONE，
  简短说明并引用既有主题；读取阶段跳过无知识记录，蒸馏阶段不据此新建长期主题。
- 运行集成测试时，应为测试子进程提供临时 HOME，防止本机 behavior.cooperate_mode
  污染依赖默认配置的状态展示断言。不要为适配测试去修改用户的本地配置。
- Qoder 在已存在 Claude Harness skills 时会复用 .claude/skills，不额外生成 .qoder/skills。
  覆盖三平台升级时，可分别构造 Claude 安装与 Codex/Qoder 安装，不能假定共同安装总会有
  三份独立的 skill 目录。
