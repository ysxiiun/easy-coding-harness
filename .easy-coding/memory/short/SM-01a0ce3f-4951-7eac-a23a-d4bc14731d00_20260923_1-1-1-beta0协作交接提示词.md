# 协作交接提示词与持久上下文的分工

## 知识摘要

调整任务转交或执行者返回主 Agent 的体验时，统一从 `handoff_task` 的成功输出取得 `handoff_prompt`。提示词用于定位原项目、原任务和下一步；接续所需的重要信息仍由任务、计划和交接记录提供。

## 可复用知识

`handoff_task` 成功输出的提示词使用真实项目绝对路径、已解析的任务 ID 和中性的 `ec-workflow` 名称，不带发送平台特有的调用前缀。普通交接引导认领并按已有交接继续；`continuation.next_action=quality` 引导接回任务、继续审查验证，适用于实施返回与修复返回。该字段只存在于返回快照，不新增任务持久状态或审批语义；原有 `claim_task`、continuation 和协调者归属机制负责恢复。

相关 Skill 在成功交接后按用户语言展示独立可复制代码块，保留真实路径和任务 ID，随后停止交接方工作；返回时明确复制给原主 Agent。必要提醒先写入已有交接摘要，再从中摘取最多一句放进提示词。范围、约束、进度与验证证据不能只存在于提示词中，省略这句提醒也应能完整续接。

版本修改还需要同步 `docs/introduction.html` 的展示版本，由 `test/utils/version.test.ts` 检查一致性。Hook 测试的状态文案可能受到真实用户 `~/.easy-coding/config.yaml` 中协作模式的影响；本次确认默认模式断言会被 `cooperate_mode: dispatch` 干扰。遇到此类差异，应在测试子进程使用隔离的 HOME，保留用户配置；并发超时可对受影响用例采用单 worker 复测，避免将环境差异改写成产品逻辑。
