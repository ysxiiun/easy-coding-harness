## Technical Memory Candidates

- Architecture / Interface Decisions: Canonical 静态设计、Harness 本地详细证据与 `EDS:EXECUTION` 共享投影分层；设计身份使用 `revision + design_sha256`，整文摘要只作诊断。
- Engineering Rules / Workflows: 共享事件统一记录为 `easy-coding / <Agent> with Easy Coding`；写入遵循本地证据先落盘、共享 CAS 投影、acknowledgment、阶段最后迁移。
- Implementation Patterns / Reusable Approaches: 单槽 pending 禁止被新动作覆盖；可重试 CAS 冲突保留现场，旧设计动作、幂等键载荷冲突和确定性状态错误清槽；task.json 使用同目录临时文件、fsync 与原子替换。
- Pitfalls / Fix Strategies: 不能用旧 result 自动重开 implemented/blocked task；修复尝试只消费当前共享 `in_progress` acknowledgment 后的新 dispatch/result；设计同步必须淘汰受影响依赖证据和旧 plan/review/verify 指纹。
- Verification Experience: 协议适配除 hash pin 外还要覆盖并发 writer、异常 result、迁移摘要、外部 locator、崩溃对账、三平台安装产物和 npm dry-run 实际文件清单。
