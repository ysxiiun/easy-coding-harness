## 技术记忆候选

- 架构 / 接口决策：逻辑 session GC 只在新键创建前触发并预留一个容量槽；upgrade 仅对实际待升级目标做一次存量清理，dry-run 不写入。
- 工程规则 / 工作流：空闲 session 保留 7 天，仍绑定任务的 session 保留 30 天；根目录 session JSON 按最后活动时间限制为 100 个。
- 实现模式 / 复用写法：扫描所有根目录 JSON 并按内容判断，不依赖平台、PPID 或文件名字符串；时间缺失或类型错误时回退 mtime，删除前复核原内容以避开并发刷新。
- 易错点 / 修复策略：合法 JSON 也可能是数组或标量；session 应视为无效后重建，task 结构不明时必须保留 acceptance 快照。upgrade 应先执行 GC 再写新版本，避免清理失败后留下已升级版本号。
- 验证经验：生产 Python Hook 与 TypeScript 工具都要覆盖双 TTL、mtime 回退、损坏 JSON、101st 容量预留、活动/终态/未引用 acceptance 快照和 upgrade dry-run。
