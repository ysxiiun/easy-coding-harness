# 1.0.1-beta.0：TDD 配置保护与 Canonical Spec 接力

## 版本与范围

本版本调整 TDD readiness、CLI 升级及 Canonical Spec 接手和需求同步。CLI 继续只负责
确定性的文件部署与配置迁移；任务分析和源 Spec 编辑由 Agent 执行。

## TDD 检查

初始化凭据记录构建入口、覆盖率工具、报告路径和参数化门禁。已有 v1 凭据继续可读，
`sha256` 表示初始化时的快照，不作为日常可用性的判断条件。

日常检查只读取本地必要入口和参数契约。项目版本、业务依赖、父 POM、测试插件和格式
变化均可正常进入任务验证；GitLab CI 的初始化验证由初始化流程负责。

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| `needs_init` | 尚无初始化凭据 | 执行 `ec-tdd-init` |
| `ready` | 本地入口和参数契约有效 | 执行任务的测试和覆盖率验证 |
| `needs_repair` | 已有凭据或必要入口损坏 | 修复具体缺项，保留 TDD 配置 |

TDD 任务仍须提供 RED/GREEN/REFACTOR、本地测试和冻结基线下的增量覆盖率证据。构建文件
和覆盖率工具纳入当前任务的实施指纹，变化后旧验收证据失效。readiness 为 `ready` 只表示
具备验证入口，真实测试结果决定验收。状态读取不运行 Maven，也不刷新凭据。

## 升级配置保护

升级保留项目 TDD 开关和阈值、session 显式覆盖及继承关系、任务已经冻结的开关、阈值与
基线。支持 TDD 的旧配置格式迁移保持用户值；缺失字段按相应协议补齐。readiness 失败
只能报告问题，不能重置用户配置。升级时 session 清理保留带有显式 TDD 配置的会话。

托管脚本可随版本更新，项目 Maven、JaCoCo、CI 配置和已有初始化凭据继续保留。

## Spec 接手与需求变更

正式绑定的 Canonical 原文件是设计依据。任务持久化来源、设计版本、选中任务、仓库映射
以及同步状态。创建和接手返回原稿中选中任务的消费范围；后续恢复使用相同入口，不依赖
上一会话的聊天历史。接手时原稿不可访问或设计已改变，返回明确阻断原因并允许当前 Agent
修复绑定或同步设计，不能沿用交接摘要继续推进。

`resume-spec-context` 重新校验原稿、恢复选中消费范围，并记录当前 session 已加载的版本。
阶段门禁核对这份记录；设计同步后须重新恢复上下文，再更新派生计划和测试策略。

确认需求变更后，先执行 `begin-spec-change`，在任务中持久化变更说明、受影响来源任务和
原设计版本。Agent 更新绑定原稿的静态设计、令 revision 递增并验证 READY，再执行
`sync-spec-design`。同步完成后清除待同步状态、回到 ANALYSIS 并更新派生文件。待同步状态
阻止实施和验收，跨 Agent 接手后继续有效。共享执行区始终通过 writer 修改。

接手方恢复未完成回写时沿用原动作和幂等键。原事件作者用于共享事件归属，当前执行者
用于任务负责人、会话和阶段历史，两者分别传递。设计改动使受影响任务和下游重新验证；
只有共享执行进度变化时保持静态设计和已确认计划有效。

设计同步使前置依赖证明失效时，保存新设计绑定并将该依赖标为待补充。上下文恢复、补交
证明、再次修订和取消任务可以读取这一状态，创建任务、实施和验收仍执行严格的依赖检查。
状态 API 在记录阶段确认、验收结果或新增共享进度之前校验当前上下文；恢复命令不能绕过
待同步变更门禁。

## 实施单元与验证

| 单元 | 主要范围 | 验收 |
| --- | --- | --- |
| U1 | TypeScript、runtime tool、state API 三处 readiness；任务指纹 | 普通构建变化通过；缺少入口失败；旧测试证据失效 |
| U2 | upgrade、配置迁移、session 清理、任务迁移 | 升级前后开关、阈值、覆盖关系和冻结基线一致 |
| U3 | state API、task 类型、技能和主约束模板 | 跨 Agent 恢复上下文、登记需求变更、阻断未同步验收、幂等恢复并保持负责人 |
| U4 | 版本、README、CHANGELOG、项目测试策略 | 源模板与安装行为一致，构建和测试通过 |

验证使用现有 Vitest fixture 运行三平台状态脚本，覆盖创建、接手、源设计变化、待同步
交接、写回前中断以及写回成功但本地未确认的恢复。执行 `npm run lint`、
`npm run typecheck`、`npm test` 和 `npm run build`，独立 reviewer 审查同一候选。

机器校验可以证明传递了哪个版本的设计和同步是否完成；语义一致性仍须由按原稿执行的
实现、测试及独立审查共同核对。
